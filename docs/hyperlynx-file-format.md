# HyperLynx (.hyp) 文件格式说明

本说明基于 KiCad [`pcbnew/exporters/export_hyperlynx.cpp`](https://gitlab.com/kicad/code/kicad/-/blob/master/pcbnew/exporters/export_hyperlynx.cpp) 的实现，总结 HyperLynx 2.14 ASCII 文件格式的语法与约定，用于指导本扩展生成兼容的 `.hyp` 文件。

## 1. 总体约定

- **文件版本**：文件头必须包含 `{VERSION=2.14}`。
- **单位**：紧随其后的 `{UNITS=ENGLISH LENGTH}` 表示所有几何尺寸以 **英寸 (inch)** 为单位。
- **坐标系**：KiCad 内部使用纳米 (nm)，导出时通过 `iu / 1e9 / 0.0254` 转换为英寸；EasyEDA 内部使用 mil，导出时通过 `mil / 1000` 转换为英寸。
- **Y 轴方向**：HyperLynx 的 Y 轴向上。KiCad 内部 Y 轴向下，所以 KiCad 导出器对所有 Y 坐标取负；**EasyEDA 数据层的 Y 轴与 HyperLynx 同向，不可取负**，否则整板上下镜像。实测依据见第 5 节。
- **层名长度**：HyperLynx 要求层名不超过 20 个字符。KiCad 只在 `{STACKUP}` 中通过 `%.20s` 强制截断，`{DEVICES}`、`{PADSTACK}`、`{NET}` 中的层名按原样输出。本扩展在所有位置统一做截断与清理，以避免同一层在不同节中出现长短不一的名字。
- **字符串转义**：层名总是被双引号包裹，其中**允许空格**（PADS 导出的即为 `"Top Layer"`），因此不需要把空格替换成下划线；只需去掉可能破坏语法的引号与换行。
- **缩进**：KiCad 的输出器按嵌套层级每级缩进 2 个空格。

## 2. 文件结构

```text
{VERSION=2.14}
{UNITS=ENGLISH LENGTH}

{BOARD "<filename>"
  (PERIMETER_SEGMENT X1=... Y1=... X2=... Y2=...)
  ...
}

{STACKUP
  (SIGNAL T=... P=... C=... L="..." M=COPPER)
  (DIELECTRIC T=... C=... L="..." M="...")
  ...
}

{DEVICES
  (? REF="..." L="...")
  ...
}

{PADSTACK=<id>, <drill_diameter>
  ("<layer_or_MDEF>", <shape_id>, <sx>, <sy>, <angle>, M)
}

{NET="<net_name>"
  (PIN X=... Y=... R="<ref>.<pad_number>" P=<padstack_id>)
  (VIA X=... Y=... P=<padstack_id>)
  (SEG X1=... Y1=... X2=... Y2=... W=... L="<layer>")
  (ARC X1=... Y1=... X2=... Y2=... XC=... YC=... R=... W=... L="<layer>")
  {POLYGON T=POUR L="<layer>" W=<line_width> ID=<id> X=... Y=...
    (LINE X=... Y=...)
    ...
  }
  {POLYVOID ID=<id> X=... Y=...
    (LINE X=... Y=...)
    ...
  }
}

{END}
```

## 3. 各节详细说明

### 3.1 `{VERSION}` 与 `{UNITS}`

```text
{VERSION=2.14}
{UNITS=ENGLISH LENGTH}
```

- 必须位于文件最开头。
- 这两行**紧邻，中间没有空行**；`{UNITS}` 之后空一行再接 `{BOARD}`。
- 通用规则：每个顶层块的结束 `}` 之后跟一个空行（KiCad 统一输出 `}\n\n`）。

### 3.2 `{BOARD}` — 板框轮廓

```text
{BOARD "<filename>"
  (PERIMETER_SEGMENT X1=... Y1=... X2=... Y2=...)
  ...
}
```

- 板框由若干直线段 `PERIMETER_SEGMENT` 组成，按顺序连接形成闭合轮廓。
- 圆弧板框需先离散为直线段（KiCad 通过 `GetBoardPolygonOutlines()` 完成多边形化）。
- 若存在多个互不相连的外轮廓，则依次写出多组线段。
- **板内挖空不会被导出**：KiCad 只遍历 `OutlineCount()` 的外轮廓，不遍历 `HoleCount()`，因此板框内部的开槽/挖空在 `.hyp` 中丢失。
- 坐标值使用英寸。KiCad 输出精度为 `%.9f` 并对 Y 取反；本扩展不取反（见第 5.1 节），统一输出 7 位小数。
- 文件名 `"<filename>"` 仅用于标识，不影响解析。

### 3.3 `{STACKUP}` — 层叠结构

```text
{STACKUP
  (SIGNAL T=<thickness> P=<plating> C=<resistivity> L="<layer_name>" M=COPPER)
  (DIELECTRIC T=<thickness> C=<epsilon_r> L="<layer_label>" M="<material>")
  ...
}
```

条目顺序即物理层叠顺序（KiCad 直接遍历层叠描述符列表），从最外层开始向下排列。`T`、`C` 使用 `%g` 输出，因此会出现 `0.0014`、`1.724e-08` 这类形式。

- `SIGNAL`：每个导电铜层一条。
  - `T`：铜箔厚度（英寸）。
  - `P`：电镀厚度（英寸），KiCad 恒填 `0`。
  - `C`：铜的体电阻率，固定 `1.724e-8` Ω·m。
  - `L`：层名，`%.20s` 截断。
  - `M`：材料，固定为 `COPPER`。
- `DIELECTRIC`：介质层，由两种来源产生。
  - **芯板/半固化片**：`T` 介质厚度，`C` 介电常数 εr（典型 FR4 约 `4.5`）。
    - 单一子层时标签为 `DE_<上层铜层名>`（层名 `%.17s` 截断）。
    - 多子层时逐个子层输出一条，标签为 `DE<idx>_<上层铜层名>`（层名 `%.16s` 截断），`idx` 从 0 开始，各子层有独立的厚度与 εr。
    - 「上层铜层名」指遍历过程中最近一次出现的铜层名，即该介质上方的铜层。截断宽度与前缀相加后不超过 20 字符。
  - **阻焊层**：直接使用其自身层名作为 `L`（例如 `F.Mask`），**不加 `DE_` 前缀**，因为该名字本身已唯一。`M` 未指定时默认为 `"Solder Mask"`。

### 3.4 `{DEVICES}` — 器件

```text
{DEVICES
  (? REF="<designator>" L="<layer>")
  ...
}
```

- 每个器件一行，**所有**器件都会导出，不论其是否有焊盘或连接到网络。
- `?` 是器件类型占位符，KiCad 固定输出 `?`，表示类型未指定。
- `REF`：位号，如 `R1`、`U2`。若为空则输出 `EMPTY`。
- `L`：器件所在层名，取封装本身的层（顶层或底层），不做长度截断。

### 3.5 `{PADSTACK}` — 焊盘/过孔堆叠

```text
{PADSTACK=<id>, <drill_diameter>
  ("<layer_or_MDEF>", <shape_id>, <sx>, <sy>, <angle>, M)
}
```

注意首行 `{PADSTACK=...}` **不带**结尾大括号，整块由单独一行 `}` 闭合。

- `<id>`：从 0 开始的整数，在 `NET` 节中通过 `P=<id>` 引用。
  - **ID 可能不连续**：ID 在去重登记时即分配，而写出阶段会跳过铜层集合为空的 padstack，其 ID 随之空缺。这是合法的，因为引用完全依赖 `P=<id>`。
- `<drill_diameter>`：钻孔直径（英寸，`%.9f`）。SMD 焊盘无孔时填 `0`。KiCad 对焊盘与过孔一律按有孔类型处理，靠孔径为 `0` 表达无孔。
- 每个 `{PADSTACK}` 内部可包含多行，每行对应一个层上的焊盘形状。
- 层集合与铜层全集**完全相等**时使用 `"MDEF"` 占位符表示贯穿所有铜层；否则为每个出现的铜层分别写出 `"<layer_name>"`。
- 形状参数：
  - `<shape_id>`：`0` 圆形/椭圆，`1` 矩形，`2` 圆角矩形。其余形状（多边形、梯形、自定义等）不受支持，KiCad 会告警并退化为 `0`。
  - `<sx>, <sy>`：焊盘在 X/Y 方向的尺寸（英寸，`%.9f`）。
  - `<angle>`：旋转角度（度，`%.1f`），落在 `[0, 360)`。KiCad 由 `180 - 焊盘旋转角` 换算，若为负再加 `360`——**这个 `180 -` 是 Y 轴翻转的镜像补偿，不是格式要求**。因此不翻转 Y 的导出器（如本扩展）必须直接使用原始旋转角，见第 5.2 节。
  - `M`：固定标记。
- 每层独立形状的焊盘（per-layer padstack）尚不支持：KiCad 只取 `ALL_LAYERS` 的尺寸与形状，同一 padstack 各层形状相同。

### 3.6 `{NET}` — 网络

每个网络独立一节：

```text
{NET="<net_name>"
  ...objects...
}
```

网络内可包含以下对象：

#### 3.6.1 `PIN` — 焊盘引脚

```text
(PIN X=... Y=... R="<ref>.<pad_number>" P=<padstack_id>)
```

- `R`：位号与焊盘编号组合，如 `R1.1`。
- 若位号为空，使用 `EMPTY`；若焊盘编号为空，默认使用 `1`。
- 坐标取焊盘中心，精度 `%.10f`。
- `PIN` 不带层信息，所在层由引用的 `PADSTACK` 决定。
- 仅当该焊盘已登记到 padstack 映射表中才输出，未登记的焊盘会被跳过。

#### 3.6.2 `VIA` — 过孔

```text
(VIA X=... Y=... P=<padstack_id>)
```

- 坐标精度 `%.10f`，与 `PIN` 一样不带层信息，跨越的层由引用的 `PADSTACK` 决定。
- 通孔过孔的 padstack 使用 `MDEF`；盲埋孔的层集合不等于铜层全集，因此会逐层列出。
- 过孔的 padstack 形状固定为圆形，`sx = sy = 过孔外径`，角度为 `0`。

#### 3.6.3 `SEG` — 走线线段

```text
(SEG X1=... Y1=... X2=... Y2=... W=... L="<layer>")
```

- `W`：线宽（英寸）。
- `L`：所在层名，不做长度截断。
- 坐标与线宽精度均为 `%.10f`。

#### 3.6.4 `ARC` — 圆弧走线

```text
(ARC X1=... Y1=... X2=... Y2=... XC=... YC=... R=... W=... L="<layer>")
```

- `X1,Y1`：起点；`X2,Y2`：终点；`XC,YC`：圆心；`R`：半径；`W`：线宽。全部为 `%.10f`。
- 格式本身不含方向标志。实测 HyperLynx 2.14 中，`ARC` 按**顺时针**方向从 `X1,Y1` 走到 `X2,Y2` 并取小圆弧，因此若源圆弧为逆时针，必须交换起点与终点后再输出；而 `POLYGON` 内的 `CURVE` 方向正好相反，按**逆时针**取小圆弧，顺时针源弧才需要交换。
- 起终点顺序只用于确定走的是哪一段弧；圆心与半径必须与源圆弧保持一致。
- 圆弧必须与直线段分开输出：不能因为「圆弧是走线的一种」就并入 `SEG`。KiCad 的 `dyn_cast` 按**精确类型**匹配（`PCB_TRACE_T == aItem->Type()`），而不是 C++ 继承关系判断，所以尽管 `PCB_ARC` 派生自 `PCB_TRACK`，先出现的 `PCB_TRACK` 分支也不会吞掉圆弧。用 `instanceof` 之类的继承判断重写这段逻辑会导致圆弧被错误地当成直线段导出。

#### 3.6.5 `POLYGON` / `POLYVOID` — 铺铜/挖空

```text
{POLYGON T=POUR L="<layer>" W=<line_width> ID=<id> X=... Y=...
  (LINE X=... Y=...)
  ...
}
```

- `T`：多边形类型。`POUR` 为铺铜，`COPPER` 为独立铜箔区域。
- `W`：轮廓线宽（英寸）。KiCad 不输出该属性，PADS 会输出（例如 `W=0.00100`）；本扩展跟随 PADS 输出，取铺铜填充的线宽。

- **数据来源是铺铜的填充结果，不是铺铜轮廓**。KiCad 取 `GetFilledPolysList()` 并调用 `Simplify()`。因此导出前必须先完成铺铜（未填充的铺铜不会产生任何输出）。
- 铺铜按「每个铺铜 × 每个所在层 × 每个填充轮廓」展开，每个填充轮廓输出一个独立的 `{POLYGON}`。
- 顶点写法（容易踩坑）：首顶点 `p0` 会出现 **三次**——一次在 `{POLYGON ... X= Y=}` 头部，一次作为第一条 `(LINE)`，最后再重复一次用于闭合。即 `LINE` 序列完整覆盖所有顶点后再补一个 `p0`。
- `<id>` 为全局递增整数，从 1 开始，**按填充轮廓递增**（不是按铺铜或按层）。
- 挖空区域使用 `{POLYVOID ID=<id> ...}`，`ID` 与所属 `POLYGON` 相同，顶点写法一致。
- `POLYVOID` 紧跟在所属 `POLYGON` 的 `}` **之后**，是兄弟节而非嵌套在 `POLYGON` 内部。

### 3.7 未连接对象（空网络）

对于网络码 ≤ 0 的对象，KiCad 为**每个对象**单独生成一个名为 `EmptyNet<N>` 的网络节（`N` 从 0 开始全局递增），避免丢失未连接的焊盘、过孔、走线与铺铜。注意是「一个对象一个网络节」，而不是把所有未连接对象合并进一个节。

其他筛选规则：

- 所有对象都要求铜层集合非空，纯非铜层对象（丝印、阻焊等）不参与导出。
- 网络码 > 0 但网络名为空的网络会被跳过；这类网络上的对象也不满足 `netcode <= 0`，因此**不会**落入 `EmptyNet`，属于会被静默丢弃的边界情况。

### 3.8 `{END}`

HyperLynx 格式以 `{END}` 作为文件结束标记，本扩展会输出该行。

**但 KiCad 并不输出 `{END}`**：`Run()` 在 `writeNets()` 之后直接调用 `m_out->Finish()`，而 `FILE_OUTPUTFORMATTER::Finish()` 只负责把临时文件原子重命名到目标路径，不写入任何内容。因此 KiCad 导出的 `.hyp` 缺少结束标记。本扩展补上它，此处属于有意与 KiCad 不一致。

## 4. 关键实现注意事项

1. **尺寸精度**：KiCad 中 `BOARD` 与 `PADSTACK` 用 `%.9f`，`NET` 内各对象（PIN/VIA/SEG/ARC/POLYGON）用 `%.10f`，`STACKUP` 的 `T`/`C` 用 `%g`。本扩展统一用 7 位小数：EasyEDA 的 mil 数值最多 4 位小数，换算成英寸需 7 位即可无损，再多只是冗余的浮点尾数。
2. **必须使用 C 语言环境**：KiCad 用 `LOCALE_IO` 在导出期间强制切到 C locale，避免小数点被本地化成逗号而破坏文件。
3. **焊盘去重**：比较形状、类型、尺寸、角度、层集合，以及（两者均为通孔时的）钻孔。层集合始终参与比较，因此不同层的 SMD 焊盘不会错误复用同一 PADSTACK。注意 KiCad 把焊盘与过孔的类型一律置为 `PTH`，导致钻孔实际上总是参与比较——无孔情形靠孔径 `0` 表达。
4. **层集合映射**：SMD 焊盘只出现在其所在铜层；通孔焊盘和过孔出现在所有铜层，并以 `MDEF` 表示。
5. **圆弧方向**：`ARC` 无方向字段，实测按**顺时针**从 `X1,Y1` 走到 `X2,Y2` 并取小圆弧，因此源圆弧为逆时针时必须交换起终点；`POLYGON` 内的 `CURVE` 方向正好相反，按**逆时针**取小圆弧，顺时针源弧才需要交换。区分圆弧与直线段要按精确类型判断，不能用继承关系判断，否则圆弧会被当作 SEG 导出。
6. **铺铜多边形**：取铺铜的填充结果而非轮廓，`LINE` 序列末尾重复首点闭合，挖空另起 `POLYVOID` 且复用同一 `ID`。
7. **层名截断与清理**：层名超过 20 字符应截断；同一层在各节中必须使用一致的名字。层名由双引号包裹，**空格是合法的**（PADS 导出即为 `"Top Layer"`），不要替换成下划线，否则与其它工具导出的文件不一致。
8. **已知丢失的信息**：板内挖空/开槽、每层独立形状的焊盘、非受支持的焊盘形状（退化为椭圆）、网络码 > 0 但网络名为空的网络上的对象。

## 5. EasyEDA 数据源的特殊约定

以上规则来自 KiCad 实现。EasyEDA 的数据模型与 KiCad 有若干关键差异，**照搬 KiCad 的做法会产生错误的文件**。本节记录经实机验证的差异，验证方式为：把同一块 PCB 分别用 PADS 与本扩展导出，逐项比对坐标。

### 5.1 Y 轴不可取负

KiCad 内部 Y 轴向下，所以其导出器对所有 Y 坐标取负。**EasyEDA 数据层的 Y 轴与 HyperLynx 同向，不能取负。**

验证：同一块板的板框在 EasyEDA 中为 `Y ∈ [0, 826.7717] mil`，PADS 导出为 `Y ∈ [0, 0.82677] inch`，符号一致；149 个过孔中 102 个满足 `本扩展Y == -(PADS Y)`（取负时），而"同号"假设匹配 0 个——说明取负后整板被上下镜像。

注意：取负后文件内部仍然自洽（图元都落在板框内），工具不会报错，只是整板镜像。这类错误无法靠"能不能打开"来发现，只能靠与参考文件比对坐标符号。

### 5.2 焊盘角度不做镜像补偿

KiCad 的 `180 - angle` 是对 Y 轴翻转的补偿（见 3.5 节）。既然 EasyEDA 不翻转 Y，**就必须直接使用原始旋转角**，否则角度与源数据不符。

这个错误很隐蔽：矩形与椭圆焊盘具有 180° 旋转对称性，镜像后外观不变，但会导致相同焊盘因角度值不同而无法去重，产生冗余 PADSTACK。

### 5.3 板框可能存为 Polyline

板框位于板框层（layer 11），但**不一定是 Line/Arc 图元**。实测某两层板的板框是单个 `PrimitivePolyline`，其多边形源数据为矩形模式：

```text
["R", 0, 826.7717, 2007.874, 826.7717, 0, 0]
```

因此收集板框必须同时遍历 `pcb_PrimitivePolyline`、`pcb_PrimitiveLine`、`pcb_PrimitiveArc` 三类图元，并把多边形源数组离散为线段。只查 Line/Arc 会得到空结果，进而退化为包围盒兜底——这正是导出尺寸偏大的原因。

单多边形源数组的模式（`L` 直线、`ARC`/`CARC` 圆弧、`C` 贝塞尔、`R` 矩形、`CIRCLE` 圆）需要分别解析，其中 `R` 的 `x y` 是**左上角**，即 `y` 为该矩形 Y 的最大值。

### 5.4 焊盘图元 ID 是拼接而成

焊盘与器件的关联不能直接比较 ID：

- `pcb_PrimitivePad.getAll()` 返回的 ID 形如 `e1e12`
- `component.getState_Pads()` 中的 `primitiveId` 形如 `e12`（**器件内的子 ID**）

完整 ID = 器件图元 ID + 器件内焊盘 ID（`e1` + `e12` = `e1e12`）。实测按此规则可 100% 匹配（293/293）；用全等比较则匹配数为 0，导致所有 `PIN` 丢失、PADSTACK 全部变成无人引用的孤儿。

> `pcb_PrimitiveComponent.getAllPinsByPrimitiveId()` 也能取到引脚，但在实测板上逐器件调用会超时，大板慎用。

### 5.5 覆铜路径坐标单位是 0.01 inch

**这是 EasyEDA 内部唯一不使用 mil 的坐标**：`IPCB_PrimitivePouredPourFill.path` 的坐标单位为 `0.01 inch`，需 ×10 换算为 mil 后再统一处理。`lineWidth` 同理。

验证：某板覆铜原始 bbox 为 `X ∈ [0.91, 199.877]`，÷100 得 `[0.0091, 1.9988] inch`，与 PADS 的 `POLYGON` 范围 `[0.0065, 2.0014] inch` 吻合；若误按 mil 处理则整体缩小 10 倍。

另外：`getSourceStrictComplex()` 返回的复杂多边形中，**首个子多边形是外轮廓，其余是挖空**（实测所有后续子多边形的包围盒都被首个包含）。对应输出为一个 `{POLYGON}` 加若干共享同一 `ID` 的 `{POLYVOID}`。

覆铜数据需要 `pcb_PrimitivePour`（取网络与层）与 `pcb_PrimitivePoured`（取填充路径）两者配合，通过 `getState_PourPrimitiveId()` 关联。

### 5.6 必须按启用状态过滤铜层

`pcb_Layer.getAllLayers()` 返回**全部**层定义（实测 289 个），其中仅少数启用。层是否启用由 `layerStatus` 字段决定，`0`（`NOT_USED`）表示未启用。

只按层 ID 范围判断铜层会把 32 个潜在铜层全部写进 `{STACKUP}`，而实际只有 2 层——层叠结构完全错误，且通孔 PADSTACK 会列出全部 32 层。

### 5.7 铜层需按物理层叠排序

EasyEDA 的铜层 ID 为：顶层 `1`、底层 `2`、内层 `15..44`。**按 ID 升序会得到"顶层 → 底层 → 内层1 → …"，层叠顺序错误。**

正确顺序应为 顶层 → 内层 1..30 → 底层。两层板按 ID 排序恰好正确，因此该问题在两层板上不会暴露，多层板必错。
